# 大学生压力调适与心理支持 Agent 任务分工

> 团队：曹伟宁、陈玉琪、丁凯宁、孙迎勒、吴翔宇、徐依晨
> 队长假设：曹伟宁兼任核心编排和最终集成负责人；如队长另有其人，只需替换 M1 负责人。
> 状态：`not-started`、`in-progress`、`blocked`、`done`、`unknown`

## 需求分析与确认

### 目标

构建一个通过微信提供持续陪伴的压力调适 Agent：先完成情绪和压力初筛，再结合可靠知识和现实任务生成 7 天计划，通过每日文字或语音打卡记录变化，并根据反馈调整下一天任务，最终输出阶段报告。

### 范围

- 考试焦虑、求职压力、拖延、睡眠紊乱、人际压力。
- 情绪强度、睡眠、专注、回避行为等初筛维度。
- 压力管理、睡眠、呼吸训练、沟通方法的 RAG 检索。
- 求职/考试等现实任务的拆解、每日小任务和睡前放松安排。
- 微信文字、语音输入，语音转写、语音回复和每日打卡。
- 连续状态存储、计划调整、压力变化和完成情况报告。

### 排除项

- 精神疾病诊断。
- 药物或处方建议。
- 冒充心理医生或承诺治疗效果。
- 仅依靠模型单独判定自伤风险。
- 直接处理高危危机；高危内容只进入固定安全流程。

### 约束与可复用能力

- 当前项目是 Java 21、Spring Boot、微信 SDK、Qwen 工具调用和关键词 RAG 原型。
- 已有微信登录会话持久化、SILK 解码、语音转写、TTS 和睡眠 Skill，可在对应模块中复用。
- 当前工作区存在未提交改动，现有改动不属于本次分工计划的完成证据。
- 首版需要可以用 Mock/内存适配器独立测试，不能让成员必须等待真实微信、LLM 或 MongoDB 才能验收。
- 高危流程需要地区和热线配置，不能由模型编造联系方式。

## M1：核心编排与安全路由

> 负责人：**曹伟宁**
> 目标：把各模块串成一个可控的陪伴流程。
> 本地测试：Fake LLM、Fake RAG、Fake Store 和固定用户输入。

### `M1-001` 会话状态与压力初筛编排

- **依赖**：`P1-001`
- **状态**：`not-started`
- **交付**：初筛问题、当前压力源识别、会话阶段流转。

**验收标准：**

- [ ] 用户只说“毕业和求职压力很焦虑”时，系统会先共情并补问必要初筛信息，不直接生成泛化长计划。
- [ ] 初筛结果包含压力强度、睡眠影响、功能受损和主要压力源，但不输出疾病诊断。

### `M1-002` 高危固定安全流程

- **依赖**：`P1-001`
- **状态**：`not-started`
- **交付**：高危信号识别后的安全决策和固定话术模板。

**验收标准：**

- [ ] 命中高危表达后停止普通聊天、计划和知识推荐，转入安全引导。
- [ ] 引导用户联系身边可信任的人、当地急救/危机热线和专业机构；热线缺失时明确提示人工补充配置。
- [ ] 日志只记录安全状态和必要事件，不记录不必要的敏感原文。

### `M1-003` 7 天游程、动态调整与主流程集成

- **依赖**：`P1-001`；软依赖 `M2`、`M4`、`M5`、`M6`
- **状态**：`not-started`
- **交付**：每日任务生成、次日重排、阶段报告调用和微信入口适配。

**验收标准：**

- [ ] 计划同时包含调适任务、现实任务、睡前任务和每日反馈项。
- [ ] 当天任务未完成或压力上升时，第二天任务会减少负担或重新排序，不会机械追加任务。
- [ ] 端到端流程可以从用户输入走到记录打卡和报告生成。

## M2：心理健康知识库与调适 Skill

> 负责人：**陈玉琪**
> 目标：提供可追溯、边界清晰的压力调适知识能力。
> 本地测试：固定中文场景语料、期望文档集合和无结果样例。

### `M2-001` 五类场景知识整理与来源元数据

- **依赖**：`P1-001`
- **状态**：`not-started`
- **交付**：睡眠、呼吸、压力管理、拖延、人际沟通和求职/考试压力相关文档；每条包含来源、适用范围和更新时间。

**验收标准：**

- [ ] 每类场景至少有可用于演示的知识条目和关键词/标签。
- [ ] 建议内容使用非诊断、非药物表述，并对长期或明显影响功能的情况给出专业求助建议。
- [ ] 高危内容与普通调适知识分开，普通 RAG 不会覆盖安全流程。

### `M2-002` RAG 检索与调适 Skill 接口

- **依赖**：`M2-001`
- **状态**：`not-started`
- **交付**：统一检索结果结构、知识引用、呼吸/睡眠/短时放松等 Skill。

**验收标准：**

- [ ] 用户描述“面试失眠”时能召回睡眠和求职压力相关内容。
- [ ] 无命中时返回空结果或澄清请求，不编造来源。
- [ ] Skill 参数错误、缺失和不适合场景时有明确失败结果。

## M3：微信语音陪伴与每日打卡

> 负责人：**丁凯宁**
> 目标：让用户能低负担完成每日文字或语音打卡。
> 本地测试：Mock 微信客户端、固定 SILK/WAV 音频和发送消息断言。

### `M3-001` 微信文字/语音打卡路由

- **依赖**：`P1-001`
- **状态**：`not-started`
- **交付**：打卡入口、语音转写、打卡字段提取和失败重试提示。

**验收标准：**

- [ ] 语音消息能够转为文字并进入统一打卡流程。
- [ ] 无法识别或字段不完整时，系统只追问缺失项，不丢失当前会话。
- [ ] 文字打卡和语音打卡使用同一份 `CheckInRecord` 契约。

### `M3-002` 语音回复与每日提醒触发

- **依赖**：`P1-001`；软依赖 `M4`
- **状态**：`not-started`
- **交付**：打卡确认、次日任务播报和提醒调度适配器。

**验收标准：**

- [ ] 用户完成语音打卡后收到可理解的确认和下一步安排。
- [ ] 提醒失败、TTS 失败或微信发送失败时有降级文字消息。
- [ ] 提醒不会在安全流程中继续发送普通任务话术。

> 本地测试：内存适配器或测试数据库、重启恢复 fixture。

### `M4-001` 用户状态和每日记录模型

- **依赖**：`P1-001`

**验收标准：**

- [ ] 同一用户多日记录可按日期查询，并能区分不同计划版本。
- [ ] 重复提交同一天打卡不会产生不可控重复数据。
- [ ] 敏感字段有最小化存储和删除/过期策略说明。

### `M4-002` 存储接口与查询服务

- **依赖**：`M4-001`
- **状态**：`not-started`

**验收标准：**

- [ ] M1、M3、M6 可通过接口读写，不直接依赖数据库实现细节。
- [ ] 数据库不可用时能返回可识别错误，不能静默丢失打卡。
- [ ] 提供内存实现供其他模块独立测试。

## M5：现实任务拆解与 7 天游程素材

> 负责人：**吴翔宇**
> 目标：把“求职/考试压力”转成当天能完成的小任务。
> 本地测试：求职面试、考试复习、拖延和人际压力的场景 fixture。

### `M5-001` 场景任务模板

- **依赖**：`P1-001`
- **状态**：`not-started`
- **交付**：面试准备、复习、拖延启动、人际沟通四类现实任务模板，以及睡前低唤醒任务模板。

**验收标准：**

- [ ] 每个模板包含目标、预计时长、完成标准和失败后的缩小版本。
- [ ] 任务粒度控制在当天可执行，避免只输出“准备面试”这类不可验收任务。
- [ ] 模板不包含诊断、药物或强制性承诺。

### `M5-002` 任务选择与动态重排规则

- **依赖**：`M5-001`
- **状态**：`not-started`
- **交付**：根据剩余天数、压力、睡眠和完成度选择任务的规则接口。

**验收标准：**

- [ ] 面试剩余 7 天时能生成有顺序的准备任务。
- [ ] 压力升高或连续未完成时，任务数量、时长或难度会下降。
- [ ] 规则输出可解释原因，供 M1 生成自然语言回复。

## M6：变化评估与阶段报告

> 负责人：**徐依晨**
> 目标：把多日记录转成可读的变化报告和下一步建议。
> 本地测试：7 天完整 fixture、缺失一天、压力波动和任务全未完成样例。

### `M6-001` 指标与趋势计算

- **依赖**：`P1-001`；软依赖 `M4`
- **状态**：`not-started`
- **交付**：压力变化、睡眠变化、任务完成率、连续打卡天数等指标。

**验收标准：**

- [ ] 指标定义固定，明确分母、缺失值和重复打卡处理方式。
- [ ] 能区分“压力下降但任务完成率低”等非单一结论情况。
- [ ] 数据不足时输出“样本不足”，不生成确定性结论。

### `M6-002` 阶段报告生成

- **依赖**：`M6-001`、`M4-002`
- **状态**：`not-started`
- **交付**：压力变化、完成情况、有效方法、风险提醒和下一步建议的报告结构。

**验收标准：**

- [ ] 报告能被微信文字消息直接展示，也能被 TTS 读取。
- [ ] 报告不使用疾病诊断语言，不把短期数据当成医学结论。
- [ ] 报告建议与当前安全状态兼容；安全流程用户不收到普通任务建议。
